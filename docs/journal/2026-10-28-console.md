# 2026-10-28 — Console: building a UI against an API that doesn't exist yet

## Goal of the session

Build the analyst console (auth, design system, every page, tests, demo mode, screenshots)
while five other people build the backend it calls, at the same time. The only fixed point
was the v1 contract: `docs/architecture/api-contract.md` and the Zod schemas in
`@spine/shared-schema`.

## What I did, in order, and why

1. **Read the contract before anything else, and read it as code.** The prose page and the
   Zod schemas disagree in small ways (the page lists `assignee`, the schema has `assigneeId`;
   `technique` is only in the schema). ADR-0005 says the code wins, so the console follows the
   schemas, and the module guide lists every endpoint and field the console relies on so the
   lead can check the backend against it.
2. **Built the HTTP client first, test-first.** The interesting part is the 401 → refresh →
   retry dance. Refresh tokens rotate with reuse detection (ADR-0016): if two requests refresh
   with the same cookie, the second one looks like theft and the server revokes the session.
   So a burst of 401s must cost **one** refresh. I wrote the test before the code, with a fake
   backend whose refresh waits on a gate I release by hand: that's the only way to make five
   requests truly concurrent in a test. (ADR-0070)
3. **Found a second race while writing the first test.** _Hypothesis:_ a single in-flight
   promise is enough. _Experiment:_ a request is sent with token-1, another request refreshes
   and finishes, _then_ the first request's 401 arrives. _Result:_ with only the in-flight
   promise, that late 401 starts a **second** refresh (the first one already settled). The fix
   is to remember which token each request was sent with: if the session's token has changed
   since, just retry. That's the `usedToken` check in `recoverFromUnauthorized`, and it's now
   exercise 1 in the module guide.
4. **Built a fake of the whole API, not mocks of hooks.** Tests that mock `useQuery` don't test
   the refresh dance, schema validation or error parsing, which is where the bugs live. The fake
   implements `fetch`, so the real client runs unmodified, and the same fake powers the
   standalone demo. (ADR-0071)
5. **Components, then pages, each with an axe check.** Native elements did most of the
   accessibility work: `<dialog>` + `showModal()` gives focus trapping and Escape for free,
   native `<select>` beats any custom listbox. Severity is always text plus a bar glyph, never
   colour alone.
6. **Screenshots with Playwright, plus axe in a real browser.** jsdom can't compute colours, so
   the unit-level axe check disables `color-contrast`. The screenshot script injects axe into
   Chromium where contrast _can_ be measured. Result: no violations on the four pages, in both
   themes.

## Bugs and how I found them

- **The fake API didn't enforce roles.** Routes declared `access: 'admin'`, the server
  authenticated the token… and never compared the role. The UI tests still passed because
  they check that buttons are hidden, not that the server refuses. The contract test I wrote
  for the fake ("enforces authentication and roles like the API") failed with `expected 0 to
be 403`. _Lesson:_ a fake used to test authorization must itself be tested for authorization;
  deny-by-default has to be a line of code, not an intention. Fixed in `server.ts` `dispatch`.
- **An axe failure that wasn't an accessibility bug in the app.** The bar chart's SVG had
  `aria-labelledby="title desc"`, so its accessible name became the title _and_ the summary
  sentence. Tests querying `getByRole('img', { name: 'Alerts by severity' })` couldn't find it.
  _Fix:_ `aria-labelledby` for the title, `aria-describedby` for the summary. The test caught a
  real screen-reader annoyance (a very long name).
- **"Disable Sam Analyst" had no such accessible name.** The button was "Disable" plus a
  visually-hidden span with the user's name. In jsdom the computed name dropped the space and
  the query failed. Rather than fight the name computation, the button now has an explicit
  `aria-label` that _starts with_ the visible word (WCAG 2.5.3, label in name).
- **`new Date('nonsense:00Z')` is a valid date in V8** (year 2000). The audit-log date filter
  happily turned garbage into a timestamp. Now the input must match `YYYY-MM-DDTHH:mm` first.
- **A "rollback" test that would have passed without the rollback.** After a 409 the mutation
  rolls back _and_ refetches, and the refetch alone restores the card. I made the refetch fail
  too, then removed the rollback line to confirm the test now fails (it did), and restored it.
  _Lesson:_ when two mechanisms produce the same visible result, a test must disable one.
- **Timeouts under coverage.** Whole-app page tests with axe took > 5 s when all files ran in
  parallel with coverage on. Raised the per-test timeout to 20 s and Testing Library's async
  timeout to 5 s, rather than splitting tests.
- **lint-staged refused commits touching eslint-ignored files** ("File ignored because of a
  matching ignore pattern" is a warning, and `--max-warnings=0` turns it into a failure). Added
  `--no-warn-ignored` to the lint-staged eslint command (a one-word change in the root
  `package.json`) and moved the `ImportMetaEnv` typing from the ignored `vite-env.d.ts` into
  `src/env.d.ts`.

## Surprises

- jsdom 27 still has no `HTMLDialogElement.showModal()`. The test setup polyfills the small
  part we use (open attribute, close event, Escape); the real focus trap is the browser's job.
- Freezing only `Date` (`vi.useFakeTimers({ toFake: ['Date'] })`) is a great trick for UI tests
  with countdowns: fixtures, "expires in 3 minutes" and `Date.now()` all agree, while real
  timers keep user-event, polling and `waitFor` working.
- Vite statically replaces `import.meta.env.VITE_USE_FAKE_API`, so the dynamic `import()` of the
  fake disappears from production builds entirely: there's no fake chunk to ship by accident.

## Trade-offs I'd flag

- The main chunk is ~121 kB gzip, about half of it Zod (validation on every response is a
  deliberate choice, ADR-0070). Pages are lazy chunks of 0.4–4 kB gzip each.
- Polling, not push (ADR-0074). Fine for Phase 1; the outbox already holds the events an SSE
  stream would need.
- The fake validates YAML playbooks only structurally (no YAML parser in the bundle).

## Lessons

1. Build against the contract, but **write the contract test for your fake** too.
2. Native HTML elements are the best accessibility library there is.
3. For every "this test proves X", break X once and watch the test fail.
