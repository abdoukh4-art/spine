# 2026-10-28 — Auth and audit: tokens, races and the hooks nobody looks at

## Goal of the session

Implement the auth module of Spine end to end: argon2id passwords, JWT access tokens,
rotating refresh tokens with reuse detection, CSRF protection for the cookie endpoints,
login throttling, user management, the audit log, and an RBAC test that keeps the code and
the documented permission matrix in sync. Phase 0 had left a `rejectAllAuthenticator` in
`composition.ts`; at the end of the day the server had to use a real one.

## What I did, in order, and why

1. **Read before typing.** ADR-0016/0017/0019/0024, the threat model §3.2, the platform
   kernel (`access.ts`, `server.ts`, `module.ts`) and the HTTP unit test. Two things shaped
   the plan: the platform already exposes a `SpineModule.httpPlugins` extension point
   (made for the audit hook), and every dependency I needed (`jose`, `@node-rs/argon2`,
   `@fastify/cookie`) was already pinned. No new dependency in this PR.
2. **Wrote the domain first, as pure functions.** Rotation (`decideRefresh`), throttle
   (`decideThrottle`), last-admin rule, password policy, CSRF policy, audit description.
   Writing them before any I/O forced the interesting questions early. Example: should a
   revoked _and_ expired token be "expired" or "reuse"? If expiry wins, an attacker
   replaying an old stolen token never trips the alarm. So reuse is checked first, and a
   property test (`a revoked token never rotates and always counts as reuse, even when
expired`) pins it down.
3. **Then the use cases against ports, then adapters, then routes.** The use cases own the
   security-relevant **order** of steps: throttle before any database or argon2 work,
   always exactly one argon2 verification (a precomputed dummy hash for unknown emails),
   check `disabled` only after hashing. Unit tests with fakes assert that order, because an
   integration test can't see it.

## Bugs and surprises (hypothesis → experiment → result)

### 1. `@fastify/rate-limit` silently runs only one limiter per request

_Plan:_ attach two extra limiters (per IP, per username) to `/auth/login` with the
plugin's `fastify.rateLimit()` helper. _Hypothesis:_ they stack with the global 600/min
limiter. _Experiment:_ read `index.js` of v10.3.0 before relying on it. _Result:_
`rateLimitRequestHandler` sets a `rateLimitRan` symbol on the request and returns early if
it's already set. The global limiter always runs first, so the route limiters would never
have counted anything. A test with a careless assertion might even have passed. I wrote a
60-line limiter instead (atomic Lua `INCR`+`PEXPIRE`, in-memory fallback) and
[ADR-0063](../adr/0063-two-dimensional-login-throttle.md). _Lesson:_ when a library is in
the security path, read the code path you depend on.

### 2. The RBAC test found a platform bug: 400 before 401

The first run of `auth-users.test.ts` failed: `expected 400 to be 401` for an anonymous
`POST /users`. _Hypothesis:_ validation runs before authorization. _Experiment:_ Fastify's
lifecycle is `onRequest → preParsing → preValidation → validation → preHandler`, and the
platform's access hook was a `preHandler`. _Result:_ anonymous callers could read our
request schemas from 400 responses, and we parsed their bodies for nothing. Fix: move the
hook to `onRequest` (routing is already done there). Same session: a 403 in the audit log
showed `actor_type: anonymous` although we knew exactly who tried, because the principal
was attached after the role check. Two-line platform fix,
[ADR-0067](../adr/0067-authorize-before-body-parsing.md). _Lesson:_ negative tests (wrong
caller, empty body) find more bugs than happy paths.

### 3. Proving the race test actually tests the race

A concurrency test that always passes might simply never produce overlap. _Experiment:_
delete `.forUpdate('rt')` from the rotation query and rerun. _Result:_
`round 0: expected [ 200, 200 ] to deeply equal [ 200, 401 ]`: both concurrent refreshes
with the same token succeeded, which would give a thief a parallel session. With the lock
back, five rounds pass reliably. Then, for the exercises, I tried `FOR SHARE`: the test
failed at round 3 with `[ 200, 500 ]` after about one second, a deadlock that Postgres
broke by aborting one transaction. Rounds 0–2 passed because the requests didn't overlap.
_Lesson:_ mutate the code to make sure a test can fail, and repeat race tests.

### 4. A test-order dependency I created myself

The "two admins demote each other" test demotes one of the two admins, and which one is
non-deterministic. The next tests used the first admin's token and failed with 403 roughly
half the time. Fix: the race test restores the original admin through whichever admin
survived. _Lesson:_ tests that resolve races must leave a deterministic state behind.

### 5. Small ones

- `@node-rs/argon2` exports `Algorithm` as a `const enum`, which `isolatedModules` can't
  inline. I use the literal `2 as Algorithm` (Argon2id) with a comment, and a unit test
  asserts the PHC string starts with `$argon2id$v=19$m=19456,t=2,p=1$`.
- `typescript-eslint` flags `[...str].length` (`no-misused-spread`). For a code-point
  count, a `for…of` loop says what it means and keeps the linter happy.
- Prettier re-pads a whole Markdown table when one new row is wider than the column. On a
  shared index (`docs/adr/README.md`) that would rewrite every line and cause merge
  conflicts with five other branches, so I shortened my titles until the diff was
  additions only.

## Decisions I'd like a reviewer to challenge

- **Strict rotation with no grace window** ([ADR-0062](../adr/0062-strict-refresh-rotation-under-row-lock.md)):
  two console tabs refreshing at the same moment log the user out. The console has to
  single-flight its refresh.
- **The authenticator reads the user on each request (≤ 30 s cache)** ([ADR-0060](../adr/0060-authenticator-reloads-user-with-short-cache.md)):
  this trades statelessness for fast revocation.
- **Missing `Origin` rejected even in tests** ([ADR-0061](../adr/0061-csrf-origin-required-in-every-environment.md)).
- **Failed-login audit stores an HMAC fingerprint of the email, not the email** ([ADR-0064](../adr/0064-audit-log-write-policy.md)).

## What's left

- The console must implement single-flight refresh and send `X-Spine-CSRF: 1` + `Origin`.
- `cli/seed.ts` (demo workstream) can call `createAuthModule(deps).seedUsers([...])`.
- Other modules should write explicit audit entries via `AuditRecorder.record(entry, trx)`.
- The RBAC matrix lists every documented route; as modules land, any path or policy that
  differs from `rbac.md` will fail the test with a diff. That's the point.
