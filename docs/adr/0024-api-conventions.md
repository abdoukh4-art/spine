# ADR-0024: API conventions — URI versioning, RFC 9457 problem details, cursor pagination, rate limits, security headers

- **Status:** accepted
- **Date:** 2026-10-28
- **Deciders:** maintainers
- **Tags:** architecture, security

## Context and problem statement

Consistency is a feature: integrators and the console should be able to predict every
endpoint's shape, errors and paging. Security controls at the HTTP edge (rate limits,
headers, CORS, body limits) must be uniform rather than per route.

## Decision drivers

- Predictable, documented conventions.
- Stable pagination under concurrent inserts (new alerts arrive constantly).
- Machine-readable errors.
- Defence in depth at the edge (OWASP A05 Security Misconfiguration).

## Considered options

- Versioning: **URI prefix `/api/v1`** vs header-based vs none.
- Errors: **RFC 9457 `application/problem+json`** vs ad-hoc `{error: "..."}`.
- Pagination: **opaque cursor (keyset)** vs offset/limit.

## Decision outcome

1. **Versioning:** `/api/v1/...`. Breaking changes → `/api/v2`. Additive changes are allowed in v1.
2. **Resources:** plural nouns, kebab-case paths, camelCase JSON, ISO-8601 UTC timestamps,
   UUIDv7 IDs (time-ordered, index-friendly; generated by the application).
3. **Errors:** RFC 9457 problem details:
   `{ type: "https://spine.dev/problems/<slug>", title, status, detail, instance: <requestId>, errors?: [{path, message}] }`.
   Internal errors never leak stack traces or SQL.
4. **Pagination:** `?limit=` (1–200, default 50) and `?cursor=` (opaque base64url of
   `{sortKey, id}`). Response: `{ items: [...], nextCursor: string | null }`. Keyset
   pagination is stable while new alerts are inserted, and doesn't degrade with depth like `OFFSET`.
5. **Rate limiting** (`@fastify/rate-limit`, Redis store in production): global 600 req/min
   per IP. `/auth/login` gets 10/min per IP **and** per username. Ingestion gets a separate
   bucket of 6000/min per source. `429` with `Retry-After`.
6. **Back-pressure on ingestion:** when the outbox backlog exceeds `INGEST_MAX_BACKLOG`
   (default 10 000 undispatched events), ingestion endpoints return `503` with
   `Retry-After: 5` instead of accepting work the pipeline can't absorb. This is load
   shedding at the front door, and it's also reported by `/readyz`.
7. **Security headers** (`@fastify/helmet`): strict CSP for the console (`default-src 'self'`),
   `Strict-Transport-Security` (via nginx when TLS), `X-Content-Type-Options: nosniff`,
   `Referrer-Policy: no-referrer`, `frame-ancestors 'none'`.
8. **CORS:** an allow-list from `CORS_ALLOWED_ORIGINS`, credentials only for listed origins, no wildcards.
9. **Body limits:** 1 MiB for JSON by default and 10 MiB for batch import. `raw` alert payloads are capped at 64 KiB after normalization.
10. **Health:** `GET /healthz` (liveness: the process is up) and `GET /readyz` (DB +
    Redis reachable, migrations applied, not shutting down, backlog below threshold).
    Neither requires auth, and neither reveals versions or internals.

### Consequences

- 👍 Uniform client handling, and errors are actionable.
- 👎 Cursor pagination can't jump to "page 7". Acceptable for a queue UI (infinite scroll / next).

## What would make us revisit this

- External consumers need `Accept`-header versioning or GraphQL.
